# CIA Dashboard — agent instructions

## Layout and runtime

- `backend/` and `frontend/` are separate toolchains in one Git repository; there is no root manifest or task runner. Run commands from the corresponding directory.
- Entrypoints: `backend/run.py` → `app.main:app`; frontend `frontend/src/main.tsx`.
- The SPA has no router: valid hashes are `#/dashboard`, `#/dashboard?qa=<guid>`, `#/qa`, `#/epicas/{id}`, `#/epicas/{id}/tareas`, `#/epicas/{id}/bugs`, `#/sprints`, `#/sprints?<filtros>&pagina=N&desplegado=1`, `#/pruebas`, `#/pruebas?sprint=.&persona=.&pagina=N` and `#/analitica`; malformed/extra-segment hashes fall back to the dashboard. `#/qa` deliberately has **no** filters — the person list is 35 rows in one read, and filtering would hide 30 people behind a dropdown for nothing. Sprint filters, page and disclosure state live in the hash **query** so a filtered URL is shareable; `parsearHash` normalizes them so the React Query cache key is identical for equivalent filters. `hoja` and `desplegado` are separate from `FiltrosSprint`: neither counts as an active filter, and `hoja` resets to 1 on any filter change. `ITEMS_POR_PAGINA` is the single source of truth for the **items** page size (200) and must stay aligned with the backend's `MAXIMO_ITEMS`; the stories-without-test list uses `PRUEBAS_POR_PAGINA` (50) with its own `hojaPruebasAOffset`/`totalHojasPruebas` — one shared rule for two page sizes produces an `offset` that does not match its page.
- FastAPI serves `frontend/dist` only if it exists when the app is created. Rebuilding or removing `dist` requires restarting the backend. In development run Vite separately.
- Vite proxies `/api`, `/docs` and `/openapi.json` to the hard-coded `http://127.0.0.1:8000`.

## Commands

Backend (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements.lock
Copy-Item .env.example .env  # first setup; fill organization, project and AZURE_PAT
.\.venv\Scripts\python.exe run.py
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m pytest tests/test_api.py
.\.venv\Scripts\python.exe -m pytest -k "cache"
```

Frontend (use `npm.cmd` in PowerShell on Windows):

```powershell
npm.cmd ci
npm.cmd run dev
npm.cmd test
npm.cmd test -- src/epicas/TableroTareas.test.tsx
npm.cmd test -- -t "nombre de la prueba"
npm.cmd run build  # tsc -b && vite build
npm.cmd audit --audit-level=high
```

- CI uses Python 3.14 and Node 24 on Windows. There are no lint or formatter scripts/gates.
- `backend/requirements.lock` is generated by `pip-compile --generate-hashes --output-file=requirements.lock requirements-dev.txt`; regenerate it with a separate `pip-tools` environment, never hand-edit it.
- Before handoff run backend `pytest`, `python -m pip check`, `python -m pip_audit --local`, then frontend `test`, `run build` and `audit --audit-level=high`.

## Boundaries

- Main request path: API routes → `ServicioBacklog` → domain `Protocol` ports. Compose concrete Azure/cache adapters in `backend/app/core/container.py`; keep Azure HTTP/WIQL in `backend/app/infrastructure/azure/`.
- The backlog has two tree branches: `Epic.features[].hus[].tareas[]` and direct `Epic.hus[].tareas[]`; bugs extend the hierarchy as `User Story → Bug → Task` and are optionally linked with `Related`. A shape change must update domain models, `queries.py`, repository mapping, API schemas/routes, `frontend/src/api/tipos.ts`, runtime validators in `frontend/src/api/cliente.ts`, UI and tests together.
- `frontend/src/api/cliente.ts` is the only runtime network seam. Query/mutation logic belongs in `frontend/src/epicas/hooks.ts`; presentational descendants receive props and emit events, while data-connected pages/rows may use hooks. `componentes/NavegacionGlobal.tsx` is presentational: `App` supplies `vista`, `configurado`, `refrescando` and `onRefrescar`.
- Sprints and analytics are **progressive-disclosure** views, and that is a design rule, not an implementation detail. Opening `#/sprints` must not download items: `useItems(filtros, activo)` stays disabled until a filter is active or `desplegado=1` is in the hash. Do not reintroduce always-on tables. Presentational primitives are `CintaSprints` (sprints as a *sequence*, not a set), `LineaVeredicto`, `Embudo` and `TarjetaSenal`; pure logic for them lives in `sprints/cinta.ts`, `sprints/veredicto.ts` and `sprints/fechas.ts`, testable without React. No UI framework: the problem the redesign solved was information hierarchy, not missing components.
- QA writing is a **separate, opt-in capability** (ADR-11). `EscrituraBacklogPort` / `infrastructure/azure/escritura.py` are the only write path; `RepositorioBacklogPort` and `repository.py` stay read-only. Any change to the editable field set must update `ActualizacionQA`, the JSON Patch builder, `api/schemas.py`, `frontend/src/api/tipos.ts`, the `EdicionInline` form and tests together.
- **The write whitelist is `CAMPOS_POR_TIPO` in `domain/models.py`, and it is per type** (amended ADR-11, 2026-09-27). Editable types: Bug, User Story, Task, Test Plan, Test Suite, Test Case. Epic, Feature and Issue are absent on purpose. The type is read from Azure on every save — never taken from the client, or it would not be a whitelist. Two facts make this non-negotiable: `Test Plan`/`Test Suite` have **none** of `Priority`/`Tags`/`Description` (0 of 44 and 0 of 457, and the fields do not appear in the response at all), and **Azure accepts writing them anyway** — `validateOnly` validates the value, not the field's existence in the type. So an extra control writes an orphan field with no error at all.
- A corollary for the frontend: the form must never decide which controls to show from its own assumptions. `EdicionInline` takes `camposEditables` and, when present, it **overrides** the `mostrar*` booleans; `/api/pruebas/activos` sends that list derived from the same table. Two copies of the whitelist is how you ship a control the backend rejects.
- `mostrarPrioridad={false}` on the story/task boards predates Fase 5 and is a **UI choice, not a field limitation**: `Priority` was measured present on 601/601 stories and 4904/4904 tasks. Do not "fix" it silently; it is a product decision to revisit.
- Sprint/people/analytics views are **read-only and served by the local index** (`application/indice.py` + `ItemIndice`). They are the reason the index exists: WIQL returns no field values, iteration paths cannot be enumerated with a query (the iterations API answers 401 on a read PAT) and tags cannot be filtered server-side. `IndiceWorkItems` must stay `async` (`asyncio.Lock`, not `threading`) and must never know an Azure field name — the repository owns that translation. `filtrar()` must not call the repository after the first load; tests assert the call count.
- The QA test-estate lives in a **second index** (`IndicePruebas`, `application/indice_pruebas.py`, `INDEX_PRUEBAS_TTL_SEG` 900 s), never inside `IndiceWorkItems`. The 3.932 test assets are not queried when `#/sprints` opens, so merging them would double that view's cold load (~10 s → ~20 s measured) for nothing. It receives the work index because coverage is a **cross of two indexes**: the requirements a case points at (`TestedBy-Reverse`) with the stories the work index already holds.
- **A test plan cannot be opened.** Its work items have no membership relations and `…/testplan/Plans/{id}/TestCaseList` returns 404 in every api-version tried; org-level testplan returns 401. Do not add a "plan detail" endpoint — there is no membership to show. `/api/pruebas/planes` gives sprint + owner; the editable list is `/api/pruebas/activos`, where a plan offers **only its state** and the panel says why. Listing the 44 plans as the main view was rejected on purpose: they are near-empty containers.
- `CAMPOS_PRUEBA` excludes `System.Description` and `Microsoft.VSTS.TCM.Steps` **deliberately**: with them, reading the 3.431 cases returns HTTP 500; with `$expand=relations` and that field list it is 18 batches, 0 errors, 5,5 s. Steps go in an on-demand detail endpoint if ever needed.
- Coverage must stay honest about partial reads. A failed relations batch makes covered stories look uncovered, so the error travels with the data (`CargaPruebas.lotes_con_error` → `parcial: true`) and the UI says the count is an upper bound. Never publish it as a total: someone would size the writing work at 361 cases when it is 400. The two-direction cross-check lives in the tests, not in production — running it live would double the reads.
- Test-asset states map to tones, but `Ready` shares `pendiente` with `Design` on purpose: both mean "not runnable yet", and a ninth tone would need its CSS plus the three board title maps for no gain in meaning. `Microsoft.VSTS.Common.Priority` is the priority field; `System.Priority` does not exist in this template and comes back empty on all 3.431 cases.
- `/api/items` paginates with `offset`/`limite` and returns `hay_mas`. The sort is `(modificado desc, azure_id desc)` and **must stay total and deterministic**: `offset` paging is only coherent if the order never ties ambiguously, otherwise pages repeat or skip items. A cap without paging is a dead end, not a limit. `/api/pruebas/sin-cubrir` is stable for the same reason (sprint, then id), with the no-sprint group first.
- `filtrar(sprint=…)` matches the full iteration path **or** the leaf name, so hand-written and shared URLs work. `IndiceWorkItems.filtrar` compares the leaf locally; do not make it require the exact path again.
- `GET /api/sprints` returns `total_items` and `asignados_a_sprint` because the **sum of the sprint columns is not the project total** (measured 5483 of 5651; 168 items have no assignable sprint). Any UI showing a project total must use `total_items` and say how many have no sprint; presenting the sum is a silent lie.

## Operational and security gotchas

- `backend/app/config.py` resolves `.env` by absolute path. The PAT is backend-only, `repr=False`, ignored by Git, and must never be logged, serialized or copied to frontend code. Public docs and fixtures use placeholders.
- QA writing is off unless `ESCRITURA_HABILITADA=true` **and** `AZURE_PAT_ESCRITURA` is set; `config.py` refuses to start with write enabled on a non-loopback `HOST`. Keep the write PAT separate from the read PAT. QA notes are append-only and HTML-escaped; never add `bypassRules`.
- `/api/epics` and `/api/epics/{id}/arbol` return 409 when organization, project or PAT is missing. `/api/health` is process-only; `/api/azure/estado` reports configuration and a safe verification result; `/api/epics/{id}/bugs` returns the bug projection and metrics; refresh remains available. `PATCH /api/workitems/{id}` returns 409 when writing is disabled or Azure rejects the transition, and 422 for local validation (empty body, bad tags, `rev` conflict).
- Azure descriptions are raw HTML. Render them only through `ContenidoRico`/DOMPurify; preserve its active/resource tag denylist and `FORBID_ATTR: ["style", "srcset", "formaction"]`.
- React keys must be unique per sibling array. `resaltar()` keys by `${clave}-${indice}` because a computed `clave + indice` collided at index 0 and React warned. **Asserting rendered content is not enough to catch key bugs** — a suite can be fully green while keys repeat; spy on `console.error` for React warnings when a component builds children in a loop. `resaltar` is the only place that computed a key; everything else keys off a domain value (`azure_id`, `ruta`).
- Azure states are open text. Keep the unknown/empty-state fallback to `neutro` in `tonoEstado`. `ORDEN_TONOS` is the single source of truth for board columns: the three tableros derive theirs with `columnasDesdeOrden`, so never hand-write a column list — a tone added to one board and forgotten in another fails silently. `TonoEstado` has 8 members (`nuevo`, `pendiente`, `progreso`, `verificacion`, `terminado`, `bloqueado`, `removido`, `neutro`); adding one means the union, its state set, `.estado-*` / `.punto-tono` / `.hu-card[data-tono]` / `.hu-columna[data-tono]` CSS, and the three title maps. `bloqueado` is red and `pendiente` orange on purpose: queued and stuck are different things. `tested` stays `neutro` because mapping it to `terminado` would inflate the closed count.
- The backend's `ESTADOS_CERRADOS` includes `removed`/`canceled`, so `cerrados` per sprint and signal ① count them, while the UI shows them as `removido`. Changing that shifts real numbers, so it is a product decision, not a cleanup.
- The iteration-path **root** is not a sprint: epics and features point at `<proyecto>`. Detect it as the path that is a *prefix* of others, never as the shortest path (that discards `Sprint 1` because `Sprint 10` is longer). Sprint ordering is numeric-tolerant via `clave_orden_sprint`; the project also has a legacy `Sprint_001-HUB`. There are no sprint dates available, so `sprint_actual` is the heuristic "most recently touched", not a calendar.
- `historias_sin_evidencia` in the analytics means **without the `verificado-qa` tag**, not "without notes": QA notes live in the description, which the index does not load. Do not claim note detection until descriptions are indexed.
- The Core project check must use `{org}/_apis/projects/{project}`; prefixing the project there duplicates the segment and Azure returns 401. Work Item endpoints use the project-scoped helper.
- **Revision history is per item, one call each.** `workitems/{id}/updates` has no batch form (measured), so activity is per epic and on demand: 1–254 items (median 26) and 0.3–5.8 s (median 1.2 s) measured. A global activity view would be 5.651 calls — not a view, an attack on the API. Keep `PanelActividad` closed by default; the first test asserts zero requests until it is opened.
- **Azure sends the current revision with `revisedDate = 9999-01-01T00:00:00Z`** (measured 6 of 6, plus epic 5324). `AzureBacklogRepositorio._a_fecha` turns it into `None`; the cut is `year >= 9999`, not a minimum year, so real old dates survive. Without that filter `ultima` is the year 9999 on every epic: a false value that looks like good data. Revision 1 is the creation one and also has no date, so it does not count as activity.
- **`Persona` from `revisedBy` uses `id`/`displayName`, not the domain's `guid`/`nombre`.** Hence `_a_autor_revision`, separate from `_a_persona`. Passing it through the other one does not raise — it returns `None` for every revision and the API answers "0 personas" without a single complaint.
- **Activity is a lower bound, the opposite of coverage.** A failed history batch *removes* revisions; a failed relations batch *adds* apparent gaps. So `parcial: true` plus `items_analizados` vs `items_totales` means a floor, and the UI says so. Do not reuse the coverage wording.
- **Never name a field `horas`.** `work/previewUpdates` returns 401 with the read PAT, so there are no hours anywhere in this system. The field is `revisiones` and the response carries a `nota` saying why — the number is read long after the docs.
- **Activity does not split QA from dev.** The registry says who *claims* a role; Azure says who *touched* an item. Crossing them yields a breakdown that looks measured and mixes two sources.
- **The QA registry is data, not code, and is NOT in git** (changed 2026-09-28). `backend/datos/*.json` is in `.gitignore`; requiring a commit per assignment was a ritual that bought a backup nobody asked for. Git was never the storage, only the second copy, and the two were wrongly tied together. `git clean -fd` does not touch ignored files, but `git clean -fdx` does. Backup is `REGISTRO_COPIA_RUTA` in the `.env`, deliberately **empty by default**: a wrong path would hide the absence, and an empty one makes it visible. A copy that fails must NOT fail the write — the primary file is already saved, so an HTTP error would claim "not saved" about something that was. `RegistroConCopia` restores on startup only when the file is **absent**, never over one that exists: a corrupt file may still be recoverable by hand, and auto-restoring destroys the only clue.
- **Never let the UI state a fact the backend owns.** The registry is not in git, so any frontend text saying "haz `git commit`" is a lie; whoever reads it stops checking the backup. `GET /api/qa/registro` is the single source of truth for where the data lives and whether the copy works, and `AvisoRegistro` only renders that. `copia_activa` is `true` only if a destination is configured **and** the last copy was written — a destination set to a folder that does not exist is `false` with a warning, which is the real OneDrive-without-sign-in case on this machine. Tests assert the UI does not say "git" and that the text comes from the backend.
- `run.py` uses `reload=False`; `LOG_NIVEL` applies to Uvicorn and the application logger. `PERMITIR_EXTERNO=true` only disables the loopback guard; it does not add authentication, TLS or rate limiting.
- The backend has a process-local TTL cache; React Query has a second frontend cache. The refresh button invalidates both, but an external `POST /api/epics/refresh` does not invalidate data already cached in the SPA.
- The local index is a **third** cache layer with its own TTL (`INDEX_TTL_SEG`, 300 s vs 120 s for the tree). Its cold load is ~10 s (28 batches of 200) and every later query is tens of milliseconds, so the first `/api/sprints` after a restart or refresh will feel slow; that is expected, not a hang. Both `POST /api/epics/refresh` and `PATCH /api/workitems/{id}` must invalidate it, otherwise counts keep showing pre-edit numbers.

## Testing and Git

- Tests must not call Azure or the internet. Backend tests use the protocol fakes in `backend/tests/conftest.py` (`FakeRepositorio`, `FakeEscritura`, `SabanaTransporte`); the shared API fixture uses TTL 0. Frontend tests use local `QueryClient`/fetch stubs; components that call `useActualizarWorkItem` need a `QueryClientProvider` wrapper.
- CI is `.github/workflows/ci.yml`; it has no codegen, migration, Docker or deployment pipeline.
- Use Conventional Commits and keep one logical change per commit. Inspect `git status`/`git diff --cached`; never stage `.env`, PATs, `.venv`, `node_modules`, `dist` or build metadata. Do not amend, reset, force-push or push without explicit authorization.
- `docs/10-auditoria.md` is the risk/backlog reference; executable manifests, source and CI take precedence when prose conflicts.
